# SKILL_ECONOMICS

## 1. Purpose

This document defines the economic model of the skill ecosystem.

Its purpose is to prevent two opposite mistakes:

1. treating skills as if they were only cheap prompt wrappers with no institutional consequence, and
2. treating every skill as if it required frontier-model budgets and enterprise-scale procurement.

The system must distinguish between:
- **skill templates**,
- **evaluated skills**,
- **governance-grade skills**.

These tiers have different:
- development costs,
- maintenance burdens,
- evaluation requirements,
- replacement risks,
- capture surfaces.

This document complements:
- `SKILLS.md`
- `SKILL_REGISTRY.md`
- `SKILL_EVALUATION.md`
- `POLITICAL_ECONOMY.md`
- `MINIMUM_VIABLE_PNYX.md`
- `GOVERNANCE.md`

The goal is not to inflate the skill problem.
The goal is to scale the economic model to the actual maturity level of the skill.

---

## 2. Core Premise

A skill is not the same thing as a model.

A skill is a structured public reasoning instrument that may include:
- role framing,
- decomposition rules,
- packet scaffolds,
- adversarial prompts,
- value overlays,
- output contracts,
- review hooks,
- evaluation harness integration.

The result of a skill depends on:
- the underlying model,
- the context window and context packing,
- the task domain,
- the runtime scaffold,
- the evaluation loop.

Therefore:
- skills matter,
- models matter,
- evaluation matters,
- and none of these should be treated as sufficient by themselves.

---

## 3. Skill Tiers

## 3.1 Tier 1 — Skill Templates

Skill templates are lightweight, forkable, public-facing skill definitions.

Typical examples:
- value overlays,
- critique roles,
- packet formatting contracts,
- routing prompts,
- dissent-preservation prompts,
- capture-risk prompts,
- local translation wrappers.

Their main properties are:
- low creation cost,
- high forkability,
- low entry barrier,
- weak legitimacy by default,
- strong usefulness for experimentation and public commons building.

Tier 1 skills are suitable for:
- early prototyping,
- community experimentation,
- public tool release,
- bootstrap exploration,
- model comparison.

Tier 1 skills are **not** automatically suitable for default public governance use.

---

## 3.2 Tier 2 — Evaluated Skills

Evaluated skills are skills that have passed a defined task and regression loop.

They include:
- stable task suites,
- expected-output-property checks,
- adversarial tasks,
- failure ledgers,
- versioning,
- promotion and demotion rules.

Their main properties are:
- moderate creation and maintenance cost,
- better comparability,
- better public trust,
- meaningful portability if well structured.

Tier 2 is the expected bootstrap tier for most Pnyx skills.

---

## 3.3 Tier 3 — Governance-Grade Skills

Governance-grade skills are evaluated skills that also satisfy higher institutional requirements.

These include:
- stronger benchmark coverage,
- longitudinal drift checks,
- challenge history,
- public audit fitness,
- portability planning,
- fallback plans,
- provider disclosure,
- incident response expectations,
- class-specific failure controls.

Tier 3 skills are not required for every function from day one.

They are required when a skill becomes:
- default in public packets,
- structurally relied upon in core classes,
- hard to replace,
- consequential for rights, routing, or constitutional interpretation.

---

## 4. Economic Meaning of the Tiers

The skill ecosystem must avoid tier confusion.

### 4.1 Mistake A
Treating Tier 1 skills as if they were already governance-grade.

### 4.2 Mistake B
Assuming that every useful skill must begin at Tier 3.

### 4.3 Correct Approach
- let Tier 1 generate diversity,
- let Tier 2 filter usefulness,
- let Tier 3 carry the highest public trust burden.

This means bootstrap can grow from a broad, relatively cheap skill commons without pretending that all such skills are equally institutionally safe.

## 5. What a Skill Actually Costs

## 5.1 Template Cost
Usually includes:
- authoring,
- adaptation to the values layer,
- interface formatting,
- public documentation,
- minimal examples.

## 5.2 Evaluation Cost
Usually includes:
- task suite design,
- scoring logic,
- adversarial examples,
- regression runs,
- review notes,
- version comparison.

## 5.3 Governance Cost
Usually includes:
- challenge response,
- provenance disclosure,
- incident review,
- packet fitness checks,
- portability obligations,
- replacement planning.

## 5.4 Runtime Cost
Usually includes:
- underlying model inference,
- retrieval if used,
- logging,
- packet generation,
- monitoring.

The system must assume that template cost can be low even when governance cost is high.

---

## 6. Skill Economics Are Coupled to Model Economics

A skill may be:
- model-agnostic,
- model-tuned,
- model-dependent.

### 6.1 Model-Agnostic Skills
These are the cheapest to distribute and compare.
They are preferred for commons growth.

### 6.2 Model-Tuned Skills
These may perform better on selected runtimes,
but increase adaptation and portability cost.

### 6.3 Model-Dependent Skills
These may become hidden dependency channels.
They require stronger disclosure and replacement planning.

A skill should not quietly inherit monopoly risk from the model layer.

---

## 7. Why Templates Still Matter

Even lightweight skill templates matter politically because they shape:
- decomposition,
- framing,
- dissent preservation,
- routing pressure,
- certainty signaling,
- packet readability,
- criticism style.

A cheap skill can still become a powerful interpretive layer.

Therefore low cost does not mean low consequence.
It means low barrier to experimentation.

That is a strength if combined with evaluation.
It is a capture surface if treated as legitimacy by default.

---

## 8. Skill Supply Goals

The skill economy should aim for:

1. **Low-cost experimentation**
2. **Public forkability**
3. **Evaluation before default**
4. **Replaceability**
5. **Benchmark commons**
6. **Provider visibility**
7. **Escalation to heavier scrutiny only where dependence grows**

This makes the system more agile without becoming fully hallucinated.

---

## 9. Public Skill Commons

The system should encourage a public skill commons containing:
- class templates,
- value overlays,
- critique loops,
- packet contracts,
- routing scaffolds,
- adversarial review scaffolds,
- benchmark fixtures,
- failure examples,
- public changelogs.

The commons should make it easy to:
- copy a skill,
- adapt it,
- test it on multiple models,
- compare versions,
- publish failures.

The existence of a public commons lowers economic barriers and helps distribute interpretive power.

---

## 10. Evaluation as the Cost Multiplier

The main economic shift happens not when a skill is written,
but when a skill is trusted.

Going from:
- template → evaluated skill,
- evaluated skill → governance-grade skill,

increases cost through:
- test maintenance,
- regression discipline,
- challenge handling,
- version review,
- class-specific audits,
- portability work.

This is why `SKILL_EVALUATION.md` is central.
Without it, the system confuses creativity with reliability.

## 11. Funding Types by Tier

## 11.1 Tier 1
Suitable for:
- commons contribution,
- small grants,
- crowdfunding,
- cooperative authorship,
- public hack sessions.

## 11.2 Tier 2
Suitable for:
- benchmark grants,
- evaluation bounties,
- local civic procurement,
- community challenge pools,
- shared maintenance funds.

## 11.3 Tier 3
Suitable for:
- public-interest procurement,
- sustained maintenance contracts,
- benchmark commons funding,
- challenger capacity programs,
- portability and migration support.

Funding should match tier.
The system must not over-finance templates or under-finance evaluation.

---

## 12. Crowdfunding Role

Crowdfunding is a legitimate way to grow the skill commons, especially for:
- local issue skills,
- translation layers,
- public critique tools,
- watchdog skills,
- minority-interest skill coverage,
- accessibility layers.

But crowdfunding must not buy:
- automatic registry admission,
- default status,
- constitutional trust,
- immunity from evaluation,
- freedom from challenge.

Crowdfunding may finance capacity.
It may not confer public legitimacy by itself.

---

## 13. Provider Concentration Still Matters

Even if templates are cheap, concentration may still occur through:
- dominant model vendors,
- dominant hosting layers,
- dominant scaffolds,
- dominant evaluation suites,
- dominant default packet generators.

The system must therefore track not only:
- who wrote the skill text,
but also:
- which model families it depends on,
- which runtimes it assumes,
- which APIs or contexts it requires,
- which evaluation harnesses it passes.

Cheap templates do not automatically eliminate economic concentration.

---

## 14. Hybrid Public Strategy

A healthy bootstrap strategy should combine:

- broad Tier 1 experimentation,
- selective Tier 2 hardening,
- very limited Tier 3 default reliance.

This keeps the system:
- agile,
- forkable,
- testable,
- less procurement-heavy,
- less cartel-prone in early stages.

This is preferable to pretending that either:
- all skills are toy prompts, or
- all skills require enterprise procurement from day one.

---

## 15. Dependency Index

The registry should still maintain a dependency view for skills, but scaled to tier.

For Tier 1, look mainly at:
- model specificity,
- scaffold dependence,
- community forkability.

For Tier 2, add:
- benchmark dependence,
- maintenance concentration,
- challenge bottlenecks.

For Tier 3, add:
- provider concentration,
- exit cost,
- operational lock-in,
- institutional indispensability.

Dependency scrutiny should rise with institutional reliance.

---

## 16. Failure Signals

The following indicate economic distortion in the skill layer:

- Tier 1 skills treated as publicly trusted without evaluation,
- evaluation suites weaker than community enthusiasm,
- default status granted before regression evidence,
- one model family quietly dominating all “diverse” skills,
- challenge capacity weaker than skill proliferation,
- public commons growing, but public comparability not growing,
- crowdfunding creating attention winners rather than public utility,
- migration discussed only after dependence is already severe.

Repeated failure signals require tier correction, not just more skill production.

## 18. Closing Principle

Skills are lighter than full institutional mythology suggests,
but heavier than pure prompt culture admits.

A democratic system should exploit that middle ground.

It should let skills proliferate cheaply,
criticize them openly,
test them repeatedly,
promote them cautiously,
and depend on them proportionally.

The right question is not:
- Are skills cheap?
- Are skills expensive?

The right question is:
- At what tier is this skill operating,
- what trust burden does that tier justify,
- and what economic structure keeps that burden from becoming hidden power?
